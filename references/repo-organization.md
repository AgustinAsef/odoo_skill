# ADHOC repo organization — what to adopt for our own repos

Research base: `gh` CLI not installed/authenticated on this machine, so remote facts
come from WebFetch on `github.com/orgs/ingadhoc/repositories` (3 pages, 78 repos
total) and `github.com/ingadhoc/addons-repo-template`. Local facts come from
`Terceros/ingadhoc/{account-financial-tools,account-payment,odoo-argentina,
odoo-argentina-ee}` (git history + tree, inspected directly — these are read-only
mirrors per root `CLAUDE.md`, never edited).

This file only documents ADHOC's conventions and proposes what we take from them.
It does not change any workspace rule by itself — anything marked **PROPOSAL**
needs the user's decision before `CLAUDE.md` is touched.

## 1. What ADHOC does

### 1.1 Org-level grouping (78 repos, one repo = one functional area)

Confirmed via `github.com/orgs/ingadhoc/repositories` pages 1–3.

| Pattern | Examples | Reads as |
|---|---|---|
| Bare functional noun | `sale`, `purchase`, `stock`, `product`, `partner`, `project`, `website`, `hr`, `survey`, `manufacture`, `account-analytic` | one repo per Odoo functional area, same split OCA uses |
| `account-*` compound | `account-payment`, `account-financial-tools`, `account-invoicing` | account domain split further, mirrors OCA's own `account-*` repos |
| `odoo-argentina*` / `uruguay` | `odoo-argentina`, `odoo-argentina-ce`, `odoo-argentina-ee`, `argentina-sale`, `uruguay` | localization grouped by country, CE/EE split by edition |
| `miscellaneous` | — | catch-all, general purpose — direct analogue of our `modulos-olpa/` |
| Infra / docker | `docker-odoo`, `docker-compose-odoo`, `docker-odoo-adhoc`, `rancher-catalog`, `docker-odoo-saas-project` | deployment tooling lives in its own repos, never mixed into addon repos |
| Non-addon tooling | `maintainer-tools`, `maintainer-quality-tools`, `runbot-addons`, `addons-repo-template` | shared repo scaffolding lives in its own repo (see 1.3) |
| Client verticals | `odoo-clinic`, `odoo-nautical`, `odoo-logistic`, `odoo-law-tracking`, `odoo-kinesis-*`, `odoo-expresso-*` | one repo per named client/vertical, comparable to our `Implementaciones/<C>/` |

Confirms: ADHOC splits by **what the modules extend**, same axis root `CLAUDE.md`
already uses for `Compartido/`. Our current 7 groups (`account-closing-extended`,
`mail`, `mercado-libre`, `modulos-olpa`, `product_extended`, `server_tools_extended`,
`stock_extended`) map cleanly onto this pattern already — no structural change
needed here.

### 1.2 Branch model

Evidence: `git -C Terceros/ingadhoc/<repo> branch -a`.

| Repo | Local branches on remote | Default (`HEAD ->`) |
|---|---|---|
| `account-financial-tools` | `8.0` … `19.0` (one per Odoo version) + `staging.13.0` … `staging.19.0` | `19.0` |
| `account-payment` | same pattern, plus ad-hoc branches like `16.0-h-61116-jjs`, `19.0-62550-cav-rov` | `19.0` |
| `odoo-argentina` | `18.0` only | `18.0` |
| `odoo-argentina-ee` | `18.0` only | `18.0` |

Facts:

- **Branch = Odoo version**, not environment — pure OCA convention (`18.0`,
  `19.0`, …). No `main`/`master`.
- `staging.X.0` branches exist per version. Combined with the CI workflow (below)
  and commit prefix `[BOT] Bump version: …`, this is a merge-bot staging pattern:
  PRs land on `staging.X.0` first, a bot squash-merges to `X.0` and bumps the
  patch version automatically. Same mechanism OCA/Odoo's own mergebot uses.
  Evidence: `.github/workflows/pre-commit.yml` triggers on
  `push: branches: ["1[8-9].0", "[2-9][0-9].0"]` and
  `pull_request_target: branches: ["1[8-9].0*", "[2-9][0-9].0*"]` (the trailing
  `*` matches `staging.18.0`), and posts a `mergebot/pre-commit` status check.
- Occasional feature branches exist off a version branch, named
  `<version>-<ticket>-<initials>` (e.g. `19.0-62550-cav-rov`) — short-lived,
  not a standing convention like `staging.*`.
- No tags/releases were found in the local clones (`git tag` not checked
  remotely, but the version-bump-per-commit pattern below makes tags redundant:
  the manifest version at any commit on `X.0` IS the release marker).

### 1.3 Repo-level tooling files

Evidence: `Terceros/ingadhoc/account-financial-tools/{.copier-answers.yml,
.pre-commit-config.yaml, pyproject.toml, .github/}`.

| File | Purpose | Notable content |
|---|---|---|
| `.copier-answers.yml` | Marks the repo as generated from `github.com/ingadhoc/addons-repo-template` (a Copier template, ADHOC's own — not OCA's `oca-addons-repo-template`, though clearly modeled on it) | `_src_path`, `odoo_version: 18.0`, `description`, `name` |
| `.pre-commit-config.yaml` | Header: `DO NOT EDIT — GENERATED BY COPIER`. Hooks: `pre-commit-hooks` (large files, merge conflicts, yaml/xml checks, EOL fixer forcing `lf`), `OCA/odoo-pre-commit-hooks` (`oca-checks-odoo-module`, `oca-checks-po`), `astral-sh/ruff-pre-commit` (lint + format), `OCA/pylint-odoo`, `rstcheck` | Reuses OCA's own hook repos wholesale |
| `pyproject.toml` | `[tool.ruff]` line-length 120, specific ignore list; `[tool.pylint...]` with `pylint_odoo` plugin, `manifest-required-authors = "ADHOC SA"`, `license-allowed` list, curated `enable=[...]` rule set | No `[tool.black]` — ruff format replaces it |
| `.github/workflows/pre-commit.yml` | Runs `pre-commit run --all-files` on push/PR to version branches (incl. `staging.*`), blocks fork PRs from touching workflow/pre-commit files, posts `mergebot/pre-commit` status | GitHub Actions, not odoo.sh CI |
| `.github/workflows/cleaner.yml` | present, not inspected in depth | housekeeping bot job |

| `README.md` (root) | Coveralls/Code Climate badges + one-paragraph repo description + ADHOC logo footer | Generated, not curated by hand |
| `CONTRIBUTING.md` | One line: follow the `odoo-argentina` wiki guide | Not repo-specific in practice |
| `requirements.txt` | present in `account-payment`, `odoo-argentina`, `odoo-argentina-ee`; **absent** in `account-financial-tools` | Pins external Python deps, empty when a repo has none |
| `.gitattributes` | **Absent in all 4 local repos** | ADHOC does not force `eol=lf` via `.gitattributes` — the pre-commit `mixed-line-ending --fix=lf` hook does that job instead |
| `oca_dependencies.txt` | Not found in any of the 4 repos | Not part of ADHOC's pattern for these repos (may exist elsewhere in the org, not confirmed) |

### 1.5 Manifest conventions

Evidence: `account_ux/__manifest__.py`, `l10n_ar_tax/__manifest__.py`,
`pyproject.toml` (`manifest-required-authors`).

| Key | ADHOC value | Notes |
|---|---|---|
| `version` | `18.0.1.29.0` (5 segments, `18.0` prefix) | Same shape as our own `18.0.X.Y.Z` rule — this is upstream OCA convention, both orgs follow it |
| `author` | `"ADHOC SA"`, sometimes `"ADHOC SA,Odoo Community Association (OCA)"` when the module descends from an OCA module | comma-joined multi-author string; pylint enforces `manifest-required-authors = "ADHOC SA"` |
| `website` | `"www.adhoc.com.ar"` | **no `https://` prefix, no trailing slash** — differs from our own rule |
| `license` | `"AGPL-3"` (checked against an explicit `license-allowed` allowlist in `pyproject.toml`) | We don't currently enforce a license allowlist |
| `post_init_hook` / `post_load` / `uninstall_hook` | used routinely | e.g. `account_ux` has all three |
| Deprecated keys | `pylint_odoo` flags `description` and `active` as `manifest-deprecated-keys` | matches Odoo 18/19 manifest norms |
| Header boilerplate | Every module file opens with a 20-line AGPL copyright banner (`Copyright (C) 2015 ADHOC SA … All Rights Reserved`) | not something we do or should copy verbatim |

### 1.6 Commit message convention

Evidence: `git log --oneline -80` per repo, tag frequency table.

| Tag | `account-financial-tools` (80 commits) | `account-payment` (80 commits) |
|---|---|---|
| `[FIX]` | 30 | 48 |
| `[IMP]` | 25 | 13 |
| `[UPD]` | 7 | 1 |
| `[BOT]` | 6 | 11 |
| `[ADD]` | 4 | 4 |
| `[REV]` | 2 | 1 |
| `[REM]` | 1 | 0 |
| `[MOV]` | 1 | 0 |
| `[REF]` | 0 | 1 |

- Format is `[TAG] <module>: <summary>`, tag is a bracketed uppercase word, not
  a conventional-commit `type(scope):` — this is OCA's own commit tag
  vocabulary (`FIX`, `IMP`, `ADD`, `REM`, `REF`, `REV`, `MOV`, plus ADHOC's own
  `UPD`), not Conventional Commits.
- `[BOT] Bump version: <module> 18.0.1.29.0` commits are automated — the
  mergebot bumps the manifest version on every merge to a version branch. This
  is what makes their branch = release model work without separate tags.
- No `Co-Authored-By` or AI-attribution lines seen in any sampled commit.

### 1.7 Cross-repo dependencies / infra

- `odoo-argentina-ee` and `odoo-argentina` are two separate repos (CE vs EE
  split), same as our workspace already tracks (`Terceros/ingadhoc/` has both).
- `requirements.txt` at repo root pins Python deps per repo (not a
  `oca_dependencies.txt` cross-repo-checkout file — that OCA convention was not
  found in these 4 repos).
- Docker: `docker-odoo`, `docker-compose-odoo`, `docker-odoo-adhoc`,
  `docker-odoo-saas-project`, `docker-compose-context`, `rancher-catalog` are
  all separate infra repos, never mixed into an addons repo. This matches our
  own separation (`Versiones/V18/` is infra, addons repos are addons).

### 1.8 Contrast with OCA

| Aspect | OCA | ADHOC | 
|---|---|---|
| Branch = version | Yes | Yes (same) |
| `readme/` fragments assembled into `README.rst` | Yes (via `oca-gen-addon-readme`) | No — hand-written single `README.rst` |
| Repo template | `oca-addons-repo-template` (Copier) | Own fork/equivalent: `ingadhoc/addons-repo-template` (Copier) |
| Commit tags | `[FIX]/[IMP]/[ADD]/[REM]/[REF]/[REV]/[MOV]` | Same set + `[UPD]` |
| Mergebot | OCA's own (`oca-github-bot`) | ADHOC's own (`mergebot/pre-commit` status context), same staging-branch mechanism |
| `wizard/`+`report/` singular dirs | OCA's older convention | Still present in ADHOC's older modules, newer modules moved to plural — **exactly the same legacy-drift pattern our own workspace has** (root `CLAUDE.md`: "Four legacy modules break that rule and are not renamed") |

## 2. What we adopt

Everything below is a recommendation. Items that would change or conflict with
an existing rule in root `CLAUDE.md` are marked **PROPOSAL — needs user decision**;
nothing here is applied automatically.

| Area | Adopt | Rationale |
|---|---|---|
| Repo grouping by functional area | Already our model (`Compartido/<grupo>/`). No change — ADHOC's org-level split validates the approach we already use | Evidence §1.1 |
| Module-level layout: `wizard/`, `report/` (singular), `migrations/<version>/`, `i18n/`, `tests/`, `security/`, `views/`, `data/`, `models/` | Use Odoo's official singular `wizard/`/`report/` for **new** modules (see `coding-guidelines.md`) — it is what every 18.0 core addon uses; ADHOC's move to plural is inconsistent even inside ADHOC, so it is not a convention worth following | Do not rename existing dirs in modules we did not otherwise touch — same "never touch a manifest you didn't change" logic applies to directory renames |
| `version` format `18.0.X.Y.Z` | Keep as-is (already identical to ADHOC/OCA) | §1.5 confirms convergent convention |
| `author` / `website` | **Keep OURS as-is**: `author: 'OLPA GROUP'`, `website: 'https://olpagroup.com/'` (full URL + trailing slash) — do not adopt ADHOC's bare `www.adhoc.com.ar` | Root `CLAUDE.md` manifest conventions already state this explicitly; ADHOC's own inconsistency (no scheme, no slash) is not worth copying |
| Repo-level pre-commit + ruff | **PROPOSAL** — add `.pre-commit-config.yaml` (ruff + ruff-format + `OCA/pylint-odoo` + `OCA/odoo-pre-commit-hooks`) and a `pyproject.toml` `[tool.ruff]`/`[tool.pylint]` block to `Compartido/*` repos and to first-party modules at client-repo roots | We have no linting/formatting gate today. This is additive tooling, doesn't touch manifests or module code, low risk — but it is new process, needs sign-off before rolling out across 6 client repos + Compartido |
| `.gitattributes eol=lf` | Already our rule (root `CLAUDE.md`: "Every repo carries a `.gitattributes` with `eol=lf` now") — **keep ours**, do not drop it in favor of ADHOC's pre-commit-only approach | ADHOC relies solely on the `mixed-line-ending --fix=lf` hook and has no `.gitattributes`; our workspace already suffered real CRLF/LF drift (see `workspace-limpieza-2026-08-28` memory) so the belt-and-suspenders `.gitattributes` is more defensive and should stay |
| Commit message convention | **Keep ours (Conventional Commits, no AI attribution)** — do not adopt ADHOC's `[FIX]/[IMP]/[ADD]` bracket-tag style | Root `.claude/CLAUDE.md` mandates Conventional Commits; this is an explicit existing rule, ADHOC's tag vocabulary is a different (also valid, OCA-derived) scheme but switching now would be a breaking convention change across 11 repos with no material benefit |
| Branch model: version branches (`18.0`) as the addons branch, `staging.18.0` as a pre-merge integration branch, bot-driven version bump on merge | **PROPOSAL — needs user decision, and only where it doesn't conflict.** This pattern fits `Compartido/*` units (which have no odoo.sh branch constraint) but **cannot replace** the client-repo branch model in root `CLAUDE.md` (`main`/`staging`/`meli_test`/etc. are odoo.sh environment branches, not Odoo-version branches — client repos are single-version already, so a `18.0` branch there would be redundant, not additive) | Do not apply to client repos. Could apply to `Compartido/modulos-olpa` and other `Compartido/*` units if/when they need multi-version support (none currently target more than one Odoo version) — until then this has no immediate payoff and adds process for zero real benefit; flag as future option only |
| `README.rst` per module, no `readme/` fragment split | Adopt the "single hand-written `README.rst`" shape for new first-party modules that want one — lighter than OCA's fragment convention, no tooling required | Not currently a hard requirement in our workspace; low-cost to add opportunistically |
| Committing AI-assistant instruction files (`.github/copilot-instructions.md`, `.github/instructions/*.md`) | **Do NOT adopt** — see §3 | Direct conflict with an explicit existing rule |
| `requirements.txt` per repo when external Python deps exist | Adopt as a convention for `Compartido/*` repos that need it (most don't) | Cheap, explicit, matches what we'd want anyway |

## 3. What we do NOT adopt, and why

| ADHOC practice | Why we skip it |
|---|---|
| Committing `.github/copilot-instructions.md` / `.github/instructions/*.md` to the repo | Root `CLAUDE.md` hard rule: **"No AI assistant file is ever committed."** `CLAUDE.md`, `AGENTS.md`, `.claude/`, `.cursor/` stay local and gitignored in every repo. ADHOC does the opposite (these files are generated by their Copier template and committed). We keep our rule — it is explicit and pre-existing, not something this research should override |
| `[FIX]/[IMP]/[ADD]/[BOT]` bracket-tag commit convention | `.claude/CLAUDE.md` mandates Conventional Commits with no AI attribution. Switching schemes now is a workspace-wide convention change with no functional upside — flagged above as a **non-adoption**, not silently ignored |
| Bare `www.adhoc.com.ar` (no scheme, no trailing slash) for `website` | Root `CLAUDE.md` already fixes `'https://olpagroup.com/'` with scheme + trailing slash; ADHOC's own value is inconsistent with modern URL norms and not worth matching |
| 20-line AGPL copyright banner in every file header | Not our license model, not our convention; adds noise with no legal necessity for closed client work |
| `readme/DESCRIPTION.rst`/`USAGE.rst` fragment split (OCA's own convention, which ADHOC itself skipped) | ADHOC doesn't use it either (0 `readme/` dirs found) — nothing to adopt here in the first place |
| Replacing client-repo branch model (`main`/`staging`/`meli_test`/etc.) with Odoo-version branches (`18.0`) | Client repos are odoo.sh-driven, single-Odoo-version, and the branch *is* the deploy environment (root `CLAUDE.md`'s Implementations table). ADHOC's version-branch model solves a different problem (one repo serving many Odoo versions at once) that does not apply to our client repos today |
| `oca_dependencies.txt` cross-repo pinning | Not even present in the 4 ADHOC repos inspected — nothing observed to adopt |
| Coveralls/Code Climate badges, ADHOC-logo footer in root `README.md` | Cosmetic, tied to ADHOC's own CI/branding, irrelevant to us |
